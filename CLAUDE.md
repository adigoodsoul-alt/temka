# CLAUDE.md — Руководство по разработке проекта «ТЕМЩИК»

Проект: **«ТЕМЩИК»** — пиксельный Roguelike-симулятор криминального авантюриста/схематозника на Vanilla JS и HTML5 Canvas.

---

## ⚡ Главные правила и ограничения (Game Pillars)

1. **ДЕНЬГИ = ХП:**
   - Единственный ресурс выживания — `player.money`.
   - В игре **НЕТ** отдельного свойства `hp` или `health`.
   - Любой урон списывает баланс (`modifyMoney(-amount)`).
   - Если `player.money <= 0` — мгновенный переход в `GAME_OVER` (Банкротство).

2. **СТРОГО БЕЗ БОЕВОЙ СИСТЕМЫ:**
   - В проекте **НЕТ** боев, пошаговых сражений, дуэлей на ножах или перестрелок.
   - ВСЕ конфликты, проверки, облавы и сделки решаются **исключительно** через текстовые ивенты, ветвления диалогов и броски кубика:
     `d20 + Стат (Авторитет / Связи / Хитрость) >= Сложность (DC)`

3. **СТЕК: PURE VANILLA JS (ES6) + HTML5 CANVAS + CSS:**
   - **Никаких фреймворков** (React, Vue, Svelte) и **никаких тяжелых сборщиков** (Webpack, Rollup).
   - Нативные ES6 модули (`import`/`export`). Запуск через локальный HTTP сервер (`python -m http.server 3000`).
   - `Canvas` используется для атмосферного рендера, сетки и сочных эффектов `PixelFX`.
   - `UI Overlay` (`#ui-overlay`) поверх Canvas с `pointer-events: none` на контейнере и `pointer-events: auto` на интерактивных окнах.

4. **PIXELFX (ПИКСЕЛЬНЫЙ СОК):**
   - Библиотека построена на принципах **SpriteFusion** / **pixelfx**:
     - **Pixel Snapping:** координаты частиц округляются до целых чисел, кратных размеру виртуального пикселя (`Math.floor(x / pixelSize) * pixelSize`). Никакого субпиксельного размытия!
     - **Палитры:** White Core -> Vivid -> Dark Decay.
     - **Экранная отдача:** Screen Shake (тряска экрана) + Hit Flash (красно-белая вспышка при уроне, золотая при куше).
     - Вызов через фасад: `createFx('damage' | 'reward' | 'coins' | 'crit' | 'sparkle', x, y, options)`.


## 🔄 Игровой цикл и состояния (FSM)

1. `HUB`: Убежище (прокачка характеристик за деньги, выбор следующей вылазки).
2. `EXPLORATION`: Карта района / выбор точек интереса (POI).
3. `DIALOGUE`: Текстовый ивент с выбором действий и RNG-проверками.
4. `GAME_OVER`: Банкротство при падении баланса до нуля.

При смене состояния **всегда** использовать `gsm.setState(GameStates.STATE_NAME, payload)`. Не модифицировать DOM окон напрямую в обход `UIManager`.

## ⚠️ Частые ошибки, которых нужно избегать

- ❌ Не создавать класс `Enemy` или механику боя.
- ❌ Не добавлять поле `player.health` или `player.hp` — есть только `player.money`.
- ❌ Не использовать `npm install` или TypeScript без прямого указания пользователя.
- ❌ Не использовать антиалиасинг или сглаженные круги в Canvas для эффектов — частицы должны быть блочными (квадраты/кресты/прямоугольники монет).
